### How `audioMixer` works today

- **No SDL audio callback.** Stream opened with `nullptr` callback:

```357:367:D:\programming\dx11-voxel-engine-cpp\source\engine\audio\audioMixer.h

			_stream = SDL_OpenAudioDeviceStream(SDL_AUDIO_DEVICE_DEFAULT_PLAYBACK, &want, nullptr, nullptr);

```

- **Per-frame pump on game thread** from `onUpdate`:

```3810:3810:D:\programming\dx11-voxel-engine-cpp\source\app\VoxelApplication.cpp
			_audio.update();
```

```437:444:D:\programming\dx11-voxel-engine-cpp\source\engine\audio\audioMixer.h
		void update() {
			if (!_ready || !_stream) return;
			constexpr int frames = 1024;
			float buffer[frames * 2];
			while (SDL_GetAudioStreamQueued(_stream) < static_cast<int>(sizeof(buffer) * 2)) {
				mixInto(buffer, frames);
				SDL_PutAudioStreamData(_stream, buffer, static_cast<int>(sizeof(buffer)));
			}
		}
```

- **Mixing:** `mixInto()` fills stereo float, sums active voices, clamps — under `std::mutex` ```330:354:D:\programming\dx11-voxel-engine-cpp\source\engine\audio\audioMixer.h```
- **Playback trigger:** `playClip()` also locks same mutex ```227:227:D:\programming\dx11-voxel-engine-cpp\source\engine\audio\audioMixer.h```

### Thread model

**All audio mixing runs on the main game/update thread** (same thread as `_audio.update()` in `onUpdate`). Render thread is the same pipeline (`applicationPipeline` calls update then render sequentially).

### Clean migration to SDL callback / dedicated thread

**Recommended: SDL3 audio callback (simplest, no extra thread)**

1. Replace `nullptr` callback in `create()` with a static C callback + `userdata = this`.
2. Callback **only** calls `mixInto()` + writes to SDL-provided buffer (or use stream API per SDL3 docs).
3. Replace `std::mutex` on hot path with:
   - **Command queue** (SPSC): game thread pushes `{play clip ptr, volume, loop}`; callback consumes.
   - Voice state: atomic cursor/volume or double-buffer voice array swapped under brief lock.
4. Remove `_audio.update()` from `onUpdate` (or keep as no-op fallback).
5. `playClip()` becomes queue-only — never call `SDL_PutAudioStreamData` from game thread.

**Alternative: dedicated mixer thread**

- Same queue design; thread loops `mixInto` → `SDL_PutAudioStreamData`. Slightly more moving parts than callback; use if callback signature is awkward.

**Files to touch:** `D:\programming\dx11-voxel-engine-cpp\source\engine\audio\audioMixer.h` (primary; `.cpp` is empty), remove/update call at ```3810:D:\programming\dx11-voxel-engine-cpp\source\app\VoxelApplication.cpp```.

**Pitfall:** lazy sound loading (`ensureDig`, `ensureStep`, etc.) currently runs on game thread inside `play()` — keep loading on game thread; only mix/decode in callback.
